# Viking POS

Репозиторий кассы — `uslulu/viking-pos`. Рабочее дерево находится в
`pos-app/viking-pos`. ZIP-файлы в соседней папке — готовые сборки.
Для правок используйте рабочее дерево, а для сравнения с выпущенной версией —
`git show vX.Y.Z:путь/к/файлу`. Распаковывать архив для чтения кода не нужно.

## Где искать код

- Заказ и кнопка «На кухню» — `ui/pos.py`. Подготовка кухонных позиций и
  история отправок в SQL Server — `db/kitchen.py`. Формирование и печать
  чеков — `ui/printer.py`. Изменение и оплата заказа — `db/operations.py`.
- Ярлык Windows запускает `launch.vbs` → `updater.py` → `main.py`.
  Сборка релиза — `tools/publish.py`. Настройки терминала — `config.ini`,
  шаблон — `config.example.ini`.
- Порядок установки и отката — [README.md](README.md). Схема базы и жизненный
  цикл заказа — [docs/DATABASE.md](docs/DATABASE.md).

## Выпуск и проверка

- Перед работой проверьте `git status -sb`. Для задач о релизе сверьте
  `VERSION`, теги и опубликованную версию на GitHub.
- Локальная сборка без публикации —
  `python3 tools/publish.py --dry-run -n "Что нового"`. Она создаёт
  ZIP и `version.json` в `dist/`. Обычный выпуск и `--test` отправляют
  коммиты и тег на GitHub. Перед публикацией получите явное согласие пользователя.
- Обновлятор читает `releases/latest/download/version.json` при старте.
  Перед назначением релиза последним загрузите оба файла в черновик.
  После публикации скачайте публичный манифест и ZIP, сверьте версию
  и SHA‑256. Для диагностики на терминале начните с `VERSION` и хвоста
  `update.log` в папке установки.

## Подтверждено на рабочем терминале

23 ноября 2026 пользователь подтвердил обе правки в `1.1.2`.
Терминал Windows использует папку `C:\cafery\v11\warehouse`.

- Повторная отправка «На кухню» печатает новые блюда и добавленные порции.
  История хранится в `dbo.PosKitchenPrinted`. При переходе с 1.1.0
  на 1.1.1 или новее завершите ранее отправленные на кухню открытые заказы,
  поскольку в 1.1.0 история отсутствовала.
- Обычный ярлык проверяет обновления. На этой кассе Python отклонял сертификат
  с `unable to get local issuer certificate`, хотя системный `curl.exe`
  через Schannel подключался. На кассе установили `truststore` и вручную
  поставили 1.1.2. Обновлятор выбирает проверку через Windows, если
  `truststore` установлен и в `config.ini` не задан собственный `ca_file`.
