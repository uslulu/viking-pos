# Касса «Викинг»
POS-терминал для кафе на Python + PyQt6. Работает с базой Microinvest
Warehouse на MS SQL Server (столы, заказы, оплата, чеки, отчёты).

## Структура проекта
```
main.py              # Точка входа кассы
updater.py           # Проверка и установка обновлений, запускает main.py
launch.vbs           # Ярлык кассы указывает сюда (run.bat / launch.bat — то же)
rollback.bat         # Ручной откат на предыдущую версию
install.bat          # Первая установка: зависимости и config.ini
config.example.ini   # Шаблон настроек точки
app_config.py        # Чтение config.ini
db/                  # Запросы к SQL Server
ui/                  # Экраны: касса, товары, сотрудники, заказы, отчёты, печать
tools/publish.py     # Выпуск новой версии на GitHub Releases
```

## Первая установка на терминал
1. Python 3.12 из Microsoft Store (команда `py`).
2. Распакуйте архив `viking-pos-X.Y.Z.zip` в папку кассы.
3. Запустите `install.bat` — поставит зависимости и создаст `config.ini`.
4. Ярлык на рабочем столе — на `launch.vbs`.

## Ручная установка поверх старой версии
1. Закройте кассу.
2. Скопируйте папку кассы целиком (например, в `Касса_старая`) — это откат,
   если что-то пойдёт не так.
3. Распакуйте архив `viking-pos-X.Y.Z.zip` в папку кассы с заменой файлов.
   `config.ini` в архиве нет — настройки точки сохранятся.
4. Откройте `config.ini`, в секции `[update]` должно быть `enabled = true`.
5. Ярлык на рабочем столе — на `launch.vbs`. Запустите кассу, проверьте
   вход, стол, оплату и печать чека.

## Настройки точки — config.ini
Лежит рядом с `main.py`, шаблон — `config.example.ini`. Не входит в архив
обновления и никогда не перезаписывается.
- `[database] server, database` — SQL Server (Windows-аутентификация)
- `[cafe] name` — название в чеке
- `[update] enabled, url, ask` — обновления

## Обновления
`launch.vbs` → `py updater.py` → `py main.py`. При запуске updater сверяет
`VERSION` с `version.json` последнего релиза на GitHub
(`releases/latest/download/version.json`, не дольше 5 секунд).

Если есть новая версия, кассир видит окно «Доступна новая версия»:
- **Обновить сейчас** — архив скачивается, проверяется sha256, текущие файлы
  копируются в `backup/<версия>`, новые распаковываются поверх.
- **Позже** (или нет ответа 60 секунд) — касса запускается как обычно,
  предложение повторится при следующем запуске.

Защита от поломки кассы:
- нет интернета или GitHub не отвечает — касса запускается без обновления;
- новая версия падает до показа главного окна — автоматический откат из
  `backup`, эта версия больше не предлагается;
- выключили питание во время установки — откат при следующем запуске;
- новая версия запускается, но работает неправильно — закройте кассу и
  запустите `rollback.bat`: вернётся предыдущая версия, текущая больше не
  предлагается.

`ask = false` в `config.ini` — ставить обновления без вопроса.
Лог — `update.log`, вывод кассы — `main.log`.

## Выпуск новой версии
Нужен GitHub CLI (`winget install GitHub.cli`, затем один раз `gh auth login`).
Безопасный порядок — сначала тестовый выпуск на одну кассу:
```
git commit -am "..."
py tools/publish.py --test -n "Что нового"   # 1.1.0 -> 1.1.1, кассы его не видят
```
Скачайте архив из релиза на GitHub, поставьте вручную на одну кассу и
проверьте. Если всё в порядке:
```
py tools/publish.py --promote                # тот же архив — всем кассам
```
Без `--test` версия сразу становится последней. `minor` / `major` / `X.Y.Z`
вместо номера по умолчанию: `py tools/publish.py minor --test -n "..."`.
Репозиторий — в `tools/publish.ini`.
