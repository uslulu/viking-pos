# База данных

Касса не создаёт свою базу и не меняет её структуру. Она работает с уже
существующей базой **Microinvest Warehouse** на MS SQL Server: читает
справочники (сотрудники, товары, группы), пишет продажи в `Operations` и
оплаты в `Payments` в том же формате, что и Microinvest. Поэтому в той же базе
можно параллельно работать в Microinvest. Но есть одно важное ограничение по
остаткам, см. [Ограничения](#ограничения-и-допущения).

Это описание собрано по коду программы. Чтобы увидеть, какая база на самом
деле стоит на терминале, запустите [отчёт о базе](#отчёт-о-базе-на-терминале).

## Подключение

| Что | Где задаётся | По умолчанию |
|---|---|---|
| Сервер | `config.ini` → `[database] server` | `localhost\SQLEXPRESS` |
| База | `config.ini` → `[database] database` | `cafel` |
| Драйвер | `db/connection.py` | ODBC Driver 17 for SQL Server |
| Вход | `db/connection.py` | Windows-аутентификация (`Trusted_Connection`) |

- Пароля к SQL Server нет. Касса входит под той учётной записью Windows,
  под которой запущена, поэтому у неё должен быть доступ к базе в SQL Server.
- Роли в кассе (кассир / администратор) ограничивают только экраны программы.
  Права в самой базе у всех одинаковые: те, что есть у пользователя Windows.
- У каждого потока программы своё соединение. После минуты простоя оно
  проверяется запросом `SELECT 1` и при обрыве переподключается.

## Таблицы, которые использует касса

| Таблица | Что в ней | Касса читает | Касса пишет |
|---|---|---|---|
| `Operations` | Строки документов Microinvest. Продажа — `OperType = 2` | заказы, отчёты, чеки | добавляет, меняет и удаляет строки заказов |
| `Payments` | Оплаты документов | открытые/оплаченные заказы, отчёты | добавляет оплату при закрытии заказа |
| `Goods` | Товары и цены | меню кассы, справочник | экран «Товары» |
| `GoodsGroups` | Группы товаров (категории меню) | меню кассы | экран «Товары» |
| `Users` | Сотрудники и пароли | вход, «Сотрудники» | экран «Сотрудники» |
| `UsersGroups` | Группы сотрудников | — (не используется на экранах) | — |
| `Objects` | Объекты (точки, залы) | первый по имени объект — «зал» кассы | — |
| `Partners` | Контрагенты | контрагент по умолчанию для продаж | — |
| `OperationType` | Названия типов операций | — | — |
| `Store` | Складские остатки | — | **не пишет** |

### Operations — строки заказа

Одна позиция заказа — одна строка `OperType = 2`. Все строки одного заказа
связаны номером `Acct`.

| Поле | Что пишет касса |
|---|---|
| `OperType` | `2` — продажа |
| `Acct` | номер заказа (он же номер чека). Новый номер — `MAX(Acct) + 1` по всей таблице, выдаётся под блокировкой |
| `GoodID` | товар (`Goods.ID`) |
| `Qtty` | количество; «+»/«−» меняют его в той же строке |
| `PriceOut` | цена продажи за единицу. **После оплаты со скидкой — цена уже со скидкой** |
| `Discount` | процент скидки (записывается при оплате) |
| `PriceIn` | себестоимость (`Goods.PriceIn` на момент добавления) |
| `Note` | `TABLE:<номер стола>` — к какому столу относится заказ |
| `OperatorID`, `UserID` | кто добавил позицию (`Users.ID`) |
| `PartnerID` | контрагент по умолчанию: `Partners` с `IsVeryUsed` и наименьшим `ID` |
| `ObjectID` | первый объект из `Objects` |
| `Sign` | `-1` (расход) |
| `Date`, `UserRealTime` | время добавления позиции |
| `VATIn`, `VATOut`, `CurrencyID`, `CurrencyRate` | `0`, `0`, `1`, `1` |

### Payments — оплата заказа

При оплате на каждый способ оплаты пишется одна строка с тем же `Acct`.

| Поле | Значение |
|---|---|
| `Acct`, `OperType` | номер заказа, `2` |
| `Qtty` | **сумма** оплаты этим способом (поле так называется в Microinvest) |
| `Mode` | `0` — наличные, `1` — карта, `2` — перевод |
| `Type`, `Sign` | `1`, `-1` |
| `UserID`, `PartnerID`, `ObjectID`, `Date`, `UserRealTime` | кто, контрагент, объект, время оплаты |

В наличные записывается **выручка**, то есть получено минус сдача. Сдача и
полученная сумма в базе не хранятся, они есть только в напечатанном чеке.

### Users — сотрудники

- `Code` — логин, `Name` — имя в списке входа.
- `Password` — MD5 пароля в виде 32 шестнадцатеричных символов (так хранит
  Microinvest). Если в поле что-то другое, оно сравнивается с паролем как
  открытый текст. Пустое поле — вход с пустым паролем.
- `UserLevel`: `0` — кассир/официант (только экран кассы), `1` — менеджер,
  `2` — администратор (оба видят все разделы).
- Удаление сотрудника — `Deleted = 1`, строка остаётся.

### Goods и GoodsGroups — меню

- В меню кассы попадают товары с `Deleted = 0`, кнопки группируются по `GroupID`.
- Цена на кнопке — `PriceOut1`. Если она `0`, берётся цена последней продажи
  этого товара. При нажатии касса ещё раз читает `PriceOut1` из базы, чтобы
  изменение цены сразу подхватилось.
- Удаление товара — `Deleted = 1`. Удаление группы — товары переводятся
  «без группы» (`GroupID = NULL`), строка группы удаляется физически.

## Жизненный цикл заказа

```
 стол свободен ──(первая позиция)──► заказ открыт ──(оплата)──► заказ оплачен
                                      │    ▲
                                      │    └── +/−, удалить строку, добавить
                                      └──(отменить заказ)──► строки удалены
```

1. **Открытие.** Первая позиция на свободном столе создаёт новый `Acct`. Если
   этот стол уже открыт на другой кассе, позиция добавляется в существующий заказ.
2. **Открытый заказ** — строки `Operations` с `OperType = 2`, для `Acct`
   которых **нет ни одной строки в `Payments`**. Отдельного флага «открыт»
   нет: экран столов строится именно этим условием.
3. **Изменения** (+/−, удаление строки, отмена) разрешены, только пока у заказа
   нет оплаты. Проверка и изменение идут в одной транзакции под блокировкой.
4. **Оплата** (одна транзакция):
   - проверяется, что заказ не оплачен и его сумма не изменилась с момента,
     когда кассир открыл окно оплаты;
   - при скидке в каждую строку записываются цена со скидкой и процент;
   - добавляются строки `Payments`.
5. **Отмена** — строки заказа удаляются из `Operations`. В базе от отменённого
   заказа ничего не остаётся.

Две кассы не могут одновременно изменить и оплатить один заказ: обе сначала
блокируют оплату этого `Acct` (`Payments WITH (UPDLOCK, HOLDLOCK)`), и вторая
ждёт, пока первая закончит.

## Отчёты

- **Выручка, наличные / карта / перевод** — сумма `Payments.Qtty` за период по
  дате оплаты.
- **Заказов, по дням, топ товаров** — строки `Operations` оплаченных заказов
  за период по дате позиции.

Заказ, начатый до полуночи и оплаченный после, попадает в эти части отчёта в
разные дни.

## Полезные запросы (SQL Server Management Studio)

Перед любыми ручными изменениями в базе сделайте резервную копию:
```sql
BACKUP DATABASE cafel TO DISK = 'C:\Backup\cafel.bak' WITH INIT;
```

Открытые заказы:
```sql
SELECT o.Acct, MAX(o.Note) AS Стол, SUM(o.Qtty * o.PriceOut) AS Сумма, MAX(o.Date) AS Последняя
FROM Operations o
WHERE o.OperType = 2
  AND NOT EXISTS (SELECT 1 FROM Payments p WHERE p.OperType = 2 AND p.Acct = o.Acct)
GROUP BY o.Acct ORDER BY MAX(o.Date) DESC;
```

Состав заказа и его оплаты:
```sql
DECLARE @acct INT = 123;
SELECT g.Name, o.Qtty, o.PriceOut, o.Discount, o.Note, o.Date
FROM Operations o JOIN Goods g ON g.ID = o.GoodID
WHERE o.OperType = 2 AND o.Acct = @acct;
SELECT Mode, Qtty AS Сумма, Date FROM Payments WHERE OperType = 2 AND Acct = @acct;
```

Выручка за сегодня по способам оплаты:
```sql
SELECT CASE Mode WHEN 0 THEN 'Наличные' WHEN 1 THEN 'Карта' WHEN 2 THEN 'Перевод' END AS Способ,
       SUM(Qtty) AS Сумма
FROM Payments
WHERE OperType = 2 AND CAST(Date AS DATE) = CAST(GETDATE() AS DATE)
GROUP BY Mode;
```

Оплаченные заказы, где сумма оплат не равна сумме позиций:
```sql
SELECT o.Acct, SUM(o.Qtty * o.PriceOut) AS Позиции,
       (SELECT SUM(p.Qtty) FROM Payments p WHERE p.OperType = 2 AND p.Acct = o.Acct) AS Оплаты
FROM Operations o
WHERE o.OperType = 2
  AND EXISTS (SELECT 1 FROM Payments p WHERE p.OperType = 2 AND p.Acct = o.Acct)
GROUP BY o.Acct
HAVING ABS(SUM(o.Qtty * o.PriceOut)
           - (SELECT SUM(p.Qtty) FROM Payments p WHERE p.OperType = 2 AND p.Acct = o.Acct)) > 0.01;
```

## Отчёт о базе на терминале

Касса умеет сама описать подключённую базу, только читая её:

```
py -m db.report
```

Запускать в папке кассы. Отчёт показывает:
- версию SQL Server и размер базы;
- какие таблицы и колонки есть и хватает ли тех, что нужны кассе;
- сколько сотрудников, товаров и заказов;
- открытые заказы, выручку за последние 30 дней и заказы с расхождением оплат.

Результат выводится на экран и сохраняется в `db_report.txt` рядом с
программой. Паролей и персональных данных в отчёте нет: только структура и
количества.

## Ограничения и допущения

- **Остатки не списываются.** Касса не пишет в `Store`. Если остатки ведутся
  в Microinvest на этой же базе, продажи с кассы их не уменьшают.
- **Номер заказа** — `MAX(Acct) + 1` по всем типам операций, а не только по
  продажам. Номера уникальны, но в продажах могут быть пропуски.
- **Скидка** хранится как цена со скидкой в `PriceOut` и процент в `Discount`.
  Это допущение о том, как Microinvest хранит скидки; на настоящих данных
  Microinvest оно не проверялось.
- **Пароли** — MD5 без соли (формат Microinvest).
- В версиях до 1.0.1 при сдаче больше суммы заказа наличные могли не
  записаться. Такие старые оплаты в базе не исправлены, найти их можно
  запросом «сумма оплат не равна сумме позиций» выше.
- Таблицы и колонки создаёт Microinvest, касса ничего не мигрирует. Если
  колонки нет, соответствующий запрос кассы упадёт с ошибкой. Проверить это
  можно отчётом `py -m db.report`.
